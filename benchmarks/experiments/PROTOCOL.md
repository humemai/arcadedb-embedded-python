# PROTOCOL

How this benchmark harness must be operated. Every rule carries a tag saying what enforces it:

- **GATE** `<name>`: something refuses. Either one of the gate scripts `refresh_web_page.py` runs (`equivalence_check` from the 2026-10 instrument, `provenance_check`, `fairness_check`, `page_check`, `version_consistency_check`, and `version_pin_check`, in `refresh_web_page.GATES`) or a refusal in the runner or a lane at production time.
- **HAND-RUN** `claims_check`: checked only when someone runs `claims_check.py`. It is a helper library that `page_check` imports, not a gate.
- **REMEMBERED**: nothing will catch the next violation.

Companion documents: FAIRNESS.md (F1 to F15, when two numbers may be compared), PAGE-SPEC.md (what the page contains), PUBLISHING.md (how it is published), READING-RESULTS.md (how to read `results/`), CAMPAIGN.md (how a campaign is run), COMPARATORS.md (what each comparator is pinned to). The canonical-row definition is section 1 below. The page is the living artifact. A paper written from the same frozen rows pins a stable release where the page may pin a commit (DECISIONS #42), so the generated LaTeX tables T2 to T5 survive, and `page_check` pins the page's 9.99M dense cells and the prose numbers that quote them against T5.

## 1. What may reach a table

The admission filter is `make_paper_tables.load_canonical()`. Every test below runs **before** the dedupe, so a bad row can never shadow a good one by being newer. A row that reaches a cell through an overlay directory never passes the filter at all; the tags say where that matters.

- `rc == 0`. **GATE** `load_canonical`
- Scale is in `PAPER_SCALES` for that lane. Retired and exploratory tiers cannot reach a cell. **GATE** `load_canonical`
- `cpuset` is `"0-11"` or unrecorded. A partial cpuset is a parallel sweep shard, and the dedupe keys on `ts_utc` with no idea what a cpuset is. **GATE** `load_canonical` + `fairness_check.check_cpuset` (F1/F2, vacuous downstream of the loader)
- `engine_version` matches no `dev\d|SNAPSHOT`, unless the row's `engine_commit` matches the pin (`BENCH_ENGINE_COMMIT`, compared on its first nine hex characters by `make_paper_tables._commit_matches`), which is how a commit-pinned campaign's dev build is admitted. **GATE** `load_canonical._DEV_RE` for T2, T3 and the comparator rows; **GATE (report only)** for T5's time-series row, which warns on stderr and writes the row anyway; **REMEMBERED** for T5 dense, which never passes through the loader
- l3s rows carry `recall_at_10`. The synthetic sparse generator ships no ground truth, and at tiny and small both corpora hold the same document count, so nothing else tells them apart. **GATE** `load_canonical`
- Elasticsearch rows carry `server_heap` equal to `heap`. **GATE** `load_canonical` + `runner.observe_server`
- Elasticsearch rows carry `es_prune is False`. ES 9.1+ prunes by default on thresholds tuned for ELSERv2; on our SPLADE corpus that is recall 0.725-0.929 against 0.991-0.9985. **GATE** `load_canonical`
- A served row names a `d.d.d` version or carries an `@sha256` digest. `server:latest`, `server` and `unknown (PackageNotFoundError)` are not versions and the pre-release guard cannot see through them. **GATE** `load_canonical` for `runs.jsonl` rows; **GATE** `_engine_is_identifiable` in `export_web`, which withholds an ArcadeDB row whose engine string and commit identify no build
- A witness field must be present **and** equal, because bare equality passes by matching `None` against `None`. **GATE** `load_canonical`
- Dedupe key is `(lane, scale, n_docs, workload, backend, gav is not False, rep, durability_class)`, latest `ts_utc`, never `run_id`. Without the `gav` term the no-view ablation overwrites T3, and without the class term the strict arm of a write cell overwrites its relaxed twin (DECISIONS #90; a row with no class counts as relaxed, which is what it was). **GATE** `load_canonical`
- One released engine line per table. Delete preference cascades, never reorder them. **GATE** T4 refusal in `make_paper_tables` and five of f8's six bars in `make_paper_figures`; **REMEMBERED** for f8's dense bar, whose `_dense_multipass` source reads no version field, and for every other table (F5)
- Lane scripts publish; bespoke drivers investigate. Both known protocol violations were bespoke-driver rows promoted to cells, and T5's dense half is still an overlay from `dense_multipass_driver.py`, run through `runner.py --driver`. **GATE** `fairness_check.report_producers` (F6b) for `runs.jsonl` lanes, which sees no overlay record; **REMEMBERED** for every overlay-fed cell
- Every cell is N=5, or its shortfall is disclosed in `EXPECTED` and in the caption, and the disclosure is deleted when the shortfall is fixed. **N=5 is reached in two passes on the 26.10.1 measurement (DECISIONS #164): reps 1 to 3 for every arm first (`make_2610_stages.py --rep-pass 3`), reps 4 and 5 in a later pass, one whole lane at a time so every engine of a lane is topped up within days. A table landed between the passes states n=3 in its caption and in `EXPECTED`, and the later landing deletes both. Medians of three carry no rank test (the smallest two-sided Mann-Whitney p at 3 versus 3 is 0.1), so a claim under about 1.3x waits for the top-up, and the two batches are compared before they are pooled.** **GATE** `provenance_check.caption_n` over the generated `.tex` tables, skipped on a lane-scoped landing (`BENCH_ONLY_LANES`) and on a skeleton; **REMEMBERED** for T5's dense half and for the deletion half, which `if ns == {5}: continue` short-circuits
- Never publish a scale where comparators have rows and we do not; print what was withheld and why at export time. **GATE** withheld-scale guard in `export_web`
- Every artifact the page cites lives in this repository, and the superseded run is not left where it can be compared against. **GATE (report only)** `provenance_check.FEEDS`: an empty feed prints "(no result files)" and counts nothing. **GATE**: every pinned reader refuses when `<name>_<pin>` is missing
- Every overlay directory and top-level result file feeding a table records run conditions and a real version; "feeds a table" means "is opened by `make_paper_tables`". **GATE** `run_conditions`, `lane_files` and `_is_real_version` for the two lane files; **REMEMBERED** for the overlay directories T4 and T5 print, whose audit accepts any non-empty string
- A SNAPSHOT build's commit date must not predate a landmark commit. **GATE** `provenance_check.LANDMARKS`

## 2. How a cell is measured

- Published latency, throughput, percentile and memory cells run serial, one at a time, on the full cpuset. Permutation protects a ratio; it cannot restore an absolute level or a tail that never happened. **GATE** `runner.py` paper tier refuses `workers != 1`
- Every row names the instrument it was measured under (`instrument`, from `bench_common.INSTRUMENT`; rows before 2026-10 carry none and are the September instrument) and the machine (`bench_host`, refused at paper tier when unset). Rows from two instruments never share a table: a five-query analytics row beside a two-query one, or a relaxed-durability write beside an fsync one, is not a comparison. **GATE** `load_canonical`, `export_web._instrument_of`, `fairness_check.check_durability`
- The 2026-10 query set (two of its operations, `lsqb_q6` and `lsqb_q9`, excluded at the full graph network, DECISIONS #109), settled by DECISIONS #82d and extended by #104, the same on every engine of a table in its own language. Documents (6): TPC-C new-order and payment, and the four single-record operations on the same data set, 1,000 of each per repetition, ops/s over both transactions. Document analytics (5): TPC-H Q1 and Q6 plus three line-item queries with no join (top ten parts by revenue, count by ship mode, revenue by month), 100 runs each. Graph (7): point lookup, 1 hop, 2 hops, 3 hops filtered on the far end, insert, update, delete, the last three 1,000 each. Graph analytics (14): average friend age, friendships within a city, most friends, degree distribution, triangle count, and LSQB's nine pattern-matching counts (DECISIONS #104), 100 runs each, on the full social network at SF1. Dense vectors (3): search, insert into a built index then search, delete from a built index then search, the last two at the one-million tier only. Sparse vectors (1): search at three sizes. Time series (5, plus the 1 h range this lane already ran): newest reading, twelve-hour aggregate, double group-by, high-usage filter, group-by with ordering and limit, 100 runs each. Cross-model (4): the composed transaction, the same interrupted, a retrieval path, and a graph-filtered vector search. Lifecycle (4): open, one query, one write, close. Repetitions stay at five everywhere.
- Every timed query records warm latency at the median and the ninety-ninth percentile (`warm_<q>_p50_ms`, `warm_<q>_p99_ms`) and its own first-iteration number (`cold_<q>_ms`); the CELL records one cold column, `cold_first_query_ms` with `cold_first_query_name`, from the first query it ran after the database opened, and that is what a table prints (#89 as amended). No aggregated per-table statistic is published: no mean, no median, no geometric mean across query types. Peak memory and on-disk size stay on every row. Where a measurement does not apply the row records the reason in `cold_warm_na` or `cold_first_query_na` rather than leaving a blank. **GATE** `equivalence_check` for the digests; **REMEMBERED** for the split (F12, DECISIONS #89)
- Every timed query whose answer is deterministic records a canonical digest of that answer, order-insensitive unless the query defines an order, floats rounded to a fixed precision before hashing, with a small readable sample kept beside the digest so a disagreement can be read and not only detected. A query an engine cannot express is declared absent in its adapter, never silently skipped. **GATE** `equivalence_check`, which refuses a table whose engines disagree at one scale and names every declared absence (DECISIONS #88). The vector lanes keep recall against ground truth and the cross-model lane keeps its torn-state comparison, both stronger than a digest over an approximate answer.
- A summed or averaged measure is declared numeric in its query's digest spec and compared as a number whatever type the driver returns, while counts and identifiers stay exact. ArangoDB's AQL `SUM` over integer-stored values returns an integer where every other engine returns a double, which split the pricing summary seven engines to one at SF1 on an answer nobody had wrong, and a count rounded to six significant digits would let 1,234,567 and 1,234,568 agree. The declaration is per query and never per engine, so it cannot be used to make one engine's answer match another's. **GATE** `equivalence_check` over `bench_common.canonical_rows`
- The revenue total and the revenue by month count the rows they aggregate, and that count is compared exactly, because at the campaign's largest tier one lost row moves each sum by less than the digest's rounding and was detected only 10.8 and 36.5 per cent of the time (DECISIONS #94). **GATE** `equivalence_check`
- ArcadeDB SQL in this repository compares a numeric column through `BETWEEN` or a bound parameter, never against a bare decimal literal, which the engine parses at single precision so that the comparison loses the boundary value (upstream #7609, BUGS.md F42). **GATE** `equivalence_check`
- A served query that projects a temporal value is checked against its embedded twin, because the HTTP serializer prints a time bucket as a date and every bucket inside one calendar day collapses to one value (upstream #7610, BUGS.md F44); nothing is withheld today (`export_web.WITHHELD_CELLS` is empty): the served time-bucket cell was, until #7610 reached the pin on 2026-09-18, and the mechanism that held it (`equivalence_check.KNOWN_DISAGREEMENTS` and `export_web.WITHHELD_CELLS`, moved together) is described once, in PUBLISHING.md. `KNOWN_DISAGREEMENTS` holds PostgreSQL + AGE's CRUD read-backs (apache/age#2587), whose cells publish with a note and are not withheld (DECISIONS #134). **GATE** `equivalence_check`
- **Three different things stop work, and they are not interchangeable.** A query **budget** stops one query; a whole-cell **cap** stops a cell; **abandonment** stops a query early when its budget cannot buy a useful measurement. Each is a property of the work, never of the engine (#85a), so no engine is ever given more room than the engine beside it.
- **Every cell has a time cap, and a cell that exceeds it is censored with the cap named.** The cap is a property of the tier, the same for every engine on it (`runner.TIMEOUT_BY_SCALE`), sized from the measured build at the tier below with headroom and then bounded so the matrix fits: the campaign runs about nine engines at five repetitions across several lanes, and an uncapped slow engine costs days to produce a row that says no more than a censored cell does. **The value is taken from the FASTEST engine's measured cell and the MEDIAN engine's projected one, never from the slowest**, for the same reason a budget uses the median: the slowest engine is the one the cap exists to bound, so sizing the cap to it would bound nothing. When the first repetition leaves no clean row the stage skips the rest, because repeating a timeout measures nothing; the table then shows one censored cell, not five. **GATE** `runner` (the cap), **REMEMBERED** the stage script (the skip). DECISIONS #105
- **A query's budget is derived per lane, per tier and per query, from the bench host's own frozen rows.** It is three times the MEDIAN engine's measured p50 for that query at that tier, times the lane's iteration count: the median because the slowest engine is exactly what a budget exists to bound, and the factor of three because it is the one judgement in the formula and it is the same everywhere. `derive_budgets.py` writes the table into `budgets.py` from the campaign's frozen rows (`--rows results/runs_paper_oct.csv` for October; its default is September's `results/runs_paper.csv`) and never from a laptop, whose loaded and throttled timings would hand out budgets nobody needs; `budget_lookup.budget_for()` reads it. Where a tier has no measurement the lookup falls back to the lane's old flat constant and stamps `<query>_budget_source` on the row saying so, so a projection can never be mistaken on the page for a measurement. A budget may vary by lane, tier and query, because those are properties of the work; it may never vary by engine. **A budget whose own roster is the survivors of a looser bound is withheld rather than published** (#106a): if the engines that left a row for that query and tier are fewer than half the widest roster answering it anywhere, the median is measuring its own selection, and the generator names the entry with its counts and falls back to the lane's constant. The case that forced this: at TPC-H SF10 three engines of ten survived, and their median would have given a ten-times-larger corpus a four-times-smaller budget than SF1's. A query that exceeds it stops at the iteration it reached, its numbers are over those iterations, and the cell's other queries keep theirs. **GATE** `budget_lookup` (October instrument; September's lanes carry the flat constants). DECISIONS #106
- **A query whose budget cannot buy five iterations is abandoned after its cold pass.** The cold pass is already paid for, so it is kept and reported; `budget_lookup.abandon(cold_s, budget_s, iterations)` then asks whether the budget buys at least five iterations at the cold pass's own rate, five because a p50 over fewer is not a median of anything. When it does not, the row carries `<query>_abandoned` with the reason in seconds rather than the cell burning hours to prove what the first touch already showed. The test uses only the engine's own cold pass, so it is a property of the work rather than of who is running it. The other queries in the cell are unaffected. **GATE** `budget_lookup.abandon`, called by `l1_tpc`, `l2_graph` and `l4_tsbs` (October instrument); `page_check` allows `\w+_abandoned` as a recorded field. DECISIONS #107
- An indexed lower bound is not assumed to return a whole run of equal entries: an ascending range seek starts where the binary search landed inside the run and loses `floor((k-1)/2)` of the k entries at the bound (upstream #7611, BUGS.md F46), which is why the revenue query disagreed only at the size where the loss landed on a qualifying row. **GATE** `equivalence_check`
- What answer checking cannot prove: DuckDB, PostgreSQL, and SQLite share a SQL dialect closely enough that a defect in a shape all three spell the same way would agree with itself, so the independent evidence comes from the engines with their own languages, MongoDB, SurrealDB, and ArangoDB on the document lane and SurrealDB (SurrealQL), ArangoDB (AQL), MongoDB (the aggregation pipeline), and DuckPGQ (SQL/PGQ) on the graph lane; the Cypher engines there share one query text with ArcadeDB. ArcadeDB collects the most findings partly because it is the engine examined hardest here, with its source, two deployments, and hand-written SQL. **REMEMBERED**
- Every timed WRITE runs at both durability settings (DECISIONS #90): the six document operations, the three graph writes, and the cross-model transaction, once relaxed and once strict. The class is a property of the cell, not a second measurement inside one, because ArcadeDB's `txWalFlush` is per database and SurrealDB's and QuestDB's are server flags; `runner.py --durability strict` is the axis, `durability_class` is on the row and in the canonical key, and the three engines with no knob (Neo4j and the arms built on it, DuckDB including its DuckPGQ arm, LadybugDB) run once and declare it (the SurrealDB 3.2.4 server stood here as a fourth until BUGS F165 found its `sync` setting). Bulk ingest and every read path stay at the relaxed setting. **GATE** `fairness_check.check_durability` (F10b)
- Bulk ingest runs at ONE durability setting on every lane, and the reason is measured rather than assumed (DECISIONS #90a, proposed, narrowed and withdrawn on 2026-09-15 before any machine time was spent on it). A bulk load commits in batches of thousands, so the flushes over a whole ingest are seconds and a second setting buys a second build rather than a second number. The check that this is true of OUR loaders and not merely of the theory ran once, on the laptop, at micro scale on 2026-09-15: the document, graph, and cross-model lanes each load the corpus inside the write cells that already run in both classes, so twenty-one engine-lane pairs carry a relaxed and a strict build with nothing else changed, and every ratio landed between 0.92 and 1.14. No loader commits per row. A ratio far from one on any future lane is an artifact of the adapter and not a property of the engine, and that is the only thing the pair was ever going to catch. **REMEMBERED**
- A served SurrealDB cell that loses its WebSocket rebuilds the connection, re-authenticates, re-selects the namespace and database, and lets the call through once more; the sample taken across the drop is DISCARDED rather than published, and every SurrealDB row records `reconnects`, zero when nothing happened. The client's keepalive is the thing that dropped it (the SDK leaves the websockets library's 20 s ping and 20 s pong deadline in place, and a server busy answering a long query does not pong in time), so the options are set explicitly and named on the row in `surreal_ws_options`. **GATE** `test_surreal_reconnect.py`; **REMEMBERED** for the field (DECISIONS #91)
- The two dense mutation operations run at the one-million tier only, and in the order delete-then-reinsert, which is what keeps their recall exact: the ground truth after deleting a set is the original one minus that set, and re-inserting exactly that set restores it, so nothing is brute-force recomputed on any arm. The victims are drawn from the ground truth so the deletions bite, and the row records how many deleted ids the index still returned, which must be zero. **REMEMBERED** `l3d_dense.mutation_victims`
- **A served engine's restart is timed on its own container, stopped and started in place** (DECISIONS #139 item 2, `l6_restart.py`): the same container the runner started, so the data, flags, cpuset, memory cap, and network name do not change; the lane drives `docker stop` (the image's own STOPSIGNAL, SIGTERM when it declares none, then SIGKILL after a grace no engine reaches; a kill is recorded as `stop_killed_after_grace`) and `docker start` through the Docker socket, which the runner mounts for that lane alone. A restart is timed until a fixed read answers EXACTLY as it did before the stop, split at the first successful liveness call (start) and the first right answer (first answer); every probe uses a fresh client so no driver's reconnect backoff is timed. Each cycle stops twice, after a session that wrote nothing and after one that wrote a fixed batch (each record committed), and the batch must read back after the restart that follows or the cell fails. The first cycle is warm-up (its stop flushes the whole load: `shutdown_after_load_s`, not printed). The host's page cache is warm by construction (a process restart on the same machine). **GATE** `l6_restart.restart_server`, the batch read-back
- Reps per build, warmup count, settle step and query set are properties of the lane, fixed before a driver is written. **REMEMBERED** (F4)
- Never print one-build-many-passes beside per-rep-builds in one table: the two shapes price different work and the table does not show which shape a row has. **GATE (report only)** `fairness_check.check_protocol_overlays` (F4)
- Warm queries must be disjoint from cold ones. Replaying one set cannot separate residency from recall of the same queries. **GATE** `sparse_multipass_driver` protocol for l3s; **REMEMBERED** and knowingly violated for l3d, whose driver replays the `test` set on every pass after 20 untimed warmups drawn from it
- Each engine gets its own vendor-documented settle step, timed inside build so the build is timed to a queryable index, and none is skipped. **REMEMBERED**
- Ingest timers must stop on the same completion semantics across a lane, or the rates price different work. **REMEMBERED**: a new time-series adapter must stop its timer at the same semantics its lane siblings do
- The dense and sparse lanes record `ingest_s` and `index_s` separately wherever the engine has the boundary (on the dense lane every arm except those `fairness_check.PHASE_SPLIT_DECLARED` names, which index while they load), additive, with `build_s` unchanged (DECISIONS #74 item 2). The document (`l1tpc`), time-series (`l4`), and cross-model (`e2`) lanes record the same pair through `bench_common.index_split` (FAIRNESS F14), and an arm whose index is defined before the load declares `index_before_load` instead (SurrealDB on the document and time-series lanes). Engines that index while ingesting record neither and carry the total with that as the stated reason. The October dense table prints `ingest s` and `index s` beside the ingest+index pair; the sparse table prints the pair alone and records no split: pgvector's index build follows its load (COPY, then CREATE INDEX) and sits inside the same single timer on this table, and the other sparse engines index as they ingest; the September page keeps one ingest+index pair. **REMEMBERED**
- Observe conditions from the daemon and the engine; never record what the launcher meant to do. A heap that disagrees with the request fails the cell. **GATE** `runner.observe_server`
- Overlay drivers sample their own peak memory from inside the container, started before the build. `run_conditions` records the ceiling, not the use. **GATE** `bench_common.SelfMemorySampler`
- The cgroup memory reading is valid only inside a bench container; record `host` so a reader knows which they have. **REMEMBERED**
- Time every phase of a lane and record the sum beside the runner's wall clock, so the residual is visible. **GATE** `phases_accounted_s` in `l3_sparse.py`
- Every lane prints `PHASE` markers as it runs (`bench_common.PhaseBeat`), and on a timeout the runner records `timeout_client_disk_mb` and `timeout_cpu_mem`, so a cell that dies inside its budget still says which phase it was in (BUGS.md F41). **GATE** `runner.py` timeout path
- On-disk size is the writable layer plus every declared volume, destinations read from the daemon, and it must settle (two readings within 1%, else `disk_settled=False` with both). A volume in an image with no `du` is sized from a helper container (BUGS.md F38). **GATE** `runner.container_disk`
- A served row's page value is the server container's growth alone; `disk_data_mb` on the row keeps server plus client for the record. **GATE** `export_web._disk_data`
- Record IO alongside disk, taking the last `io.stat` reading: the counters are cumulative. **GATE** `CgroupSampler`
- A silently killed cell must not read as success, and a served cell whose SERVER was killed must not read as a dropped connection. **GATE** OOM inspect + non-zero exit in `runner.py`, which since 2026-09-26 also reads the server container's own `State.OOMKilled` before removal as `server_oom_killed`; `export_web._server_hit_envelope` reads an older served row as an envelope failure when the cell failed with the server's anonymous memory at 99% of its cap or more
- Prefer the loud failure: when a lane can measure something other than what was asked for, make it abort rather than annotate. **REMEMBERED**
- A server adapter that sends vectors as text must round-trip float32 exactly (`%.9f`, not `%.6f`). **REMEMBERED**: `precision_check.py` is a synthetic experiment that reads no artifact and nothing invokes it
- Never let a result object's Python type stand in for the finding, and abort an arm whose control operations moved nothing. **GATE** validity guard in `e2_hybrid.py`
- A guard that asks a driver object whether it has an attribute is not a test for absence when the object answers every name: a pymongo `Database` returns a `Collection` for any attribute, so `getattr(client, "reconnects", None)` stamped a `Collection` onto the row and killed every MongoDB document cell at its final write, after the load and after every query (BUGS.md F47). **REMEMBERED**, with a regression test on main (2026-10 instrument)
- Pin trial counts and denominators, not only outcomes. "5 of 5" bounds the failure rate only below ~45%; 200 injections bound it at ~1.5%. **HAND-RUN** `claims_check.e2_atomicity`; **GATE** `page_check` count assertions
- Re-profile on the release rather than assuming a dev build's profile transfers, and never add overlapping percentages. **REMEMBERED**
- Do not add a new recorded field to a published driver until its lane is re-run; the driver's own frozen artifacts will not have the field. **GATE** `provenance_check.check_schema_homogeneity`, which compares the measured fields of every row in a (lane, scale, workload, backend) family and reports any field some rows carry and their siblings do not

## 3. How a comparison is kept fair

- Every container in a published cell gets the full 0-11 cpuset; a client/server pair shares that one cpuset rather than each getting its own cores, so CPU competition stays inside the deployment under test. **GATE** `fairness_check.check_cpuset` (F1) + the loader filter, for the client or embedded container only; **REMEMBERED** for the server side of a pair, whose `server_cpuset` no consumer reads
- Every backend at a (lane, scale) gets the same `--memory`/`--memory-swap` and, for JVM engines, the same heap. Raising a resource for one engine obliges a re-measure of every engine at that tier. **GATE** `fairness_check.check_envelope` (F3)
- Normalize a served topology before comparing: total is `srv_cap / mem_split`, never client + server. **GATE** `_total_envelope` in `fairness_check`
- Do not compare a setting to its own absence: heaps are compared only among engines that have one, and a missing heap on an ArcadeDB row is reported as a recording gap. **GATE** `check_envelope`
- Every dense backend at a scale gets the same effective base-layer degree, read in each engine's own unit (ArcadeDB `maxConnections` as-is, hnswlib-family `M` doubled at layer 0). A row recording no degree FAILS; sqlite-vec is exempt as an exact scan, and an index with no degree at all is matched by effect instead (F7). Stamp the matched parameter from one shared function, called from both the lane and its bespoke driver. **GATE** `fairness_check.check_degree` (F7) + `l3d_dense.degree_stamp(backend)`
- Check the rows the table prints. Where a table reads an overlay, the fairness checks read that overlay too. **GATE** `_dense_rows()` swap in F3/F7
- Fit every engine's thread pools to the cpuset via `sched_getaffinity`; `os.cpu_count()`, `nproc --all` and `/proc/cpuinfo` in an adapter are the bug. **REMEMBERED** (F6; the three DuckDB lanes that ran oversubscribed were fixed on main for the 2026-10 instrument, DECISIONS #101, and September's DuckDB rows on them stay as measured)
- Verify the shared cpuset equalizes **use**, not merely the resource, before comparing p50s. **REMEMBERED** (F8 holds the measurement)
- When a campaign re-measures one engine and carries the others forward, re-run one untouched comparator as a control and record its old-vs-new delta beside the table it licenses. If the control does not reproduce, the tier is re-measured in full. **REMEMBERED** (F9)
- Measure every row in one table on the same engine release as the row beside it, so a version difference cannot be read as a configuration difference. **GATE** T4 and f8 only; **REMEMBERED** elsewhere (F5)
- Never divide a number from one experiment by a number from another and call the quotient a cost. **HAND-RUN** `claims_check._tentag` and the dense cold/warm boundary note
- Equalize a comparator's default only where leaving it makes the comparison apples-to-oranges (the four categories in section 7). **REMEMBERED**
- A durability default is relaxed only as a matched class over the whole table, never for one arm: from 2026-10 every engine that has the setting commits without waiting for the disk, each engine's setting is read out of the engine rather than assumed, and the row records what it ran as `durability` (DECISIONS #81). **GATE** `fairness_check.check_durability` (F10)
- Every timed write runs at both durability settings and the row records which one it ran; ingest runs at one setting on every lane, because a bulk load commits in batches, the flush is amortised, and a second build buys nothing (DECISIONS #90, #90a). Whether our loaders commit per batch rather than per row is settled once by a laptop check, never by a campaign axis. **GATE** `fairness_check.check_durability` (F10)
- The strict setting is a fixed per-commit tax set by the device, so every engine lands in the same narrow band when it waits and the ratio between the two settings is inversely proportional to how fast that engine's relaxed path is. It follows that a published relaxed write measures how well an engine avoids the disk as much as how fast it writes, and that under strict durability the engines converge; the framing cuts against us as much as for us, since ArcadeDB embedded's fast relaxed document insert is what makes its own multiple one of the largest. **REMEMBERED**
- A fix that costs the rival a round-trip goes only in the untimed path, or the round-trip is charged to their latency. **REMEMBERED**
- State the consequence of the memory contract that cuts against us: the JVM heap lives inside the container cap, so ArcadeDB's 24 GiB heap leaves about 12 GiB for JVM overhead and page cache while non-JVM comparators have all 36 GiB. Equal caps are what we can enforce. **REMEMBERED**
- Keep `fairness_check.DISCLOSED` empty unless an override is live, and delete a disclosure the moment the asymmetry it describes is fixed. **REMEMBERED**

## 7. Defaults and sanctioned overrides

We run every engine as shipped, and override a default only where leaving it would make the comparison meaningless. Four sanctioned categories:

1. **Resource fitting** (always applied): heap, thread pool and memory settings that fit an engine to the cell's cpuset and memory envelope. Envelope equality, not tuning.
2. **Vendor settle step**: documented bulk-load-then-query preparation, timed inside build (section 2).
3. **Operating-point matching**: where defaults put engines at different points of a quality/latency tradeoff, move them onto one point, because a latency comparison at unequal recall compares nothing.
4. **Documented escape hatch**: a default that is demonstrably pathological, tuned to the vendor's own recommendation, with the same care applied to every backend in the lane.

What we never do: per-system expert tuning beyond vendor guidance, or tuning ArcadeDB with insider knowledge not applied to comparators.

An override nobody can find is a defect, whichever way it moves the number. Every override is stamped on the row where a field exists (`es_prune`, `degree_param`, `degree_family`, `heap`, `server_heap`) **and** named in reader-facing text (table caption or page condition). `DISCLOSED WHERE = NOWHERE` marks an override not yet disclosed (the column has none left; closing them was CAMPAIGN.md section 7, item 21, and `test_overrides.py` fails on a new one). Every override a table shows is registered in `overrides.py`, which holds the row field the adapter reads back from the engine, the generated sentence, and the checks (`page_check` for the sentence, `fairness_check` F15 for the stamp, and `test_overrides.py`, which reads this table); a row's last column cites its registration as `override: <key>`.
