# PROTOCOL

How this benchmark harness must be operated. Every rule carries a tag saying what enforces it:

- **GATE** `<name>`: something refuses. Either one of the gate scripts `refresh_web_page.py` runs (`equivalence_check`, `resource_check`, `provenance_check`, `fairness_check`, `page_check`, `version_consistency_check`, and `version_pin_check`, in `refresh_web_page.GATES`) or a refusal in the runner or a lane at production time.
- **HAND-RUN** `claims_check`: checked only when someone runs `claims_check.py`. It is a helper library that `page_check` imports, not a gate.
- **REMEMBERED**: nothing will catch the next violation.

Companion documents: FAIRNESS.md (F1 to F15, when two numbers may be compared), PAGE-SPEC.md (what the page contains), PUBLISHING.md (how it is published), READING-RESULTS.md (how to read `results/`), CAMPAIGN.md (how a campaign is run), COMPARATORS.md (what each comparator is pinned to). The canonical-row definition is section 1 below. The generated LaTeX tables T2 to T5 survive because a paper pins a stable release where the page may pin a commit (DECISIONS #42), and `page_check` pins the page's 9.99M dense cells and the prose numbers that quote them against T5.

## 1. What may reach a table

The admission filter is `make_paper_tables.load_canonical()`. Every test below runs **before** the dedupe, so a bad row can never shadow a good one by being newer. A row that reaches a cell through an overlay directory never passes the filter at all; the tags say where that matters.

- `rc == 0`. **GATE** `load_canonical`
- Scale is in `PAPER_SCALES` for that lane. Retired and exploratory tiers cannot reach a cell. **GATE** `load_canonical`
- `cpuset` is `"0-11"` or unrecorded. A partial cpuset is a parallel sweep shard, and the dedupe keys on `ts_utc` with no idea what a cpuset is. **GATE** `load_canonical` + `fairness_check.check_cpuset` (F1/F2, vacuous downstream of the loader)
- `engine_version` matches no `dev\d|SNAPSHOT`, unless the row's `engine_commit` matches the pin (`BENCH_ENGINE_COMMIT`, compared on its first nine hex characters by `make_paper_tables._commit_matches`), which is how a commit-pinned campaign's dev build is admitted. **GATE** `load_canonical._DEV_RE` for T2, T3 and the comparator rows; **GATE (report only)** for T5's time-series row, which warns on stderr and writes the row anyway; **REMEMBERED** for T5 dense, which never passes through the loader
- l3s rows carry `recall_at_10`. The synthetic sparse generator ships no ground truth, and at tiny and small both corpora hold the same document count, so nothing else tells them apart. **GATE** `load_canonical`
- Elasticsearch rows carry `server_heap` equal to `heap`. **GATE** `load_canonical` + `runner.observe_server`
- Elasticsearch rows carry `es_prune is False`. ES 9.1+ prunes by default on thresholds tuned for ELSERv2; on our SPLADE corpus that costs recall. **GATE** `load_canonical`
- A served row names a `d.d.d` version or carries an `@sha256` digest. `server:latest`, `server` and `unknown (PackageNotFoundError)` are not versions and the pre-release guard cannot see through them. **GATE** `load_canonical` for `runs.jsonl` rows; **GATE** `_engine_is_identifiable` in `export_web`, which withholds an ArcadeDB row whose engine string and commit identify no build
- A witness field must be present **and** equal, because bare equality passes by matching `None` against `None`. **GATE** `load_canonical`
- Dedupe key is `(lane, scale, n_docs, workload, backend, gav is not False, rep, durability_class)`, latest `ts_utc`, never `run_id`. Without the `gav` term the no-view ablation overwrites T3, and without the class term the strict arm of a write cell overwrites its relaxed twin (DECISIONS #90; a row with no class counts as relaxed, which is what it was). **GATE** `load_canonical`
- One released engine line per table. Delete preference cascades, never reorder them. **GATE** T4 refusal in `make_paper_tables` and five of f8's six bars in `make_paper_figures`; **REMEMBERED** for f8's dense bar, whose `_dense_multipass` source reads no version field, and for every other table (F5)
- Lane scripts publish; bespoke drivers investigate. Both known protocol violations were bespoke-driver rows promoted to cells, and T5's dense half is still an overlay from `dense_multipass_driver.py`, run through `runner.py --driver`. **GATE** `fairness_check.report_producers` (F6b) for `runs.jsonl` lanes, which sees no overlay record; **REMEMBERED** for every overlay-fed cell
- Every cell is N=5, or its shortfall is disclosed in `EXPECTED` and in the caption, and the disclosure is deleted when the shortfall is fixed. **N=5 is reached in two passes on the 26.10.1 measurement (DECISIONS #164): reps 1 to 3 for every arm first, reps 4 and 5 in a later pass, one whole lane at a time so every engine of a lane is topped up within days. A table landed between the passes states n=3 in its caption and in `EXPECTED`, and the later landing deletes both. Medians of three carry no rank test (the smallest two-sided Mann-Whitney p at 3 versus 3 is 0.1), so a claim under about 1.3x waits for the top-up, and the two batches are compared before they are pooled.** **GATE** `provenance_check.caption_n` over the generated `.tex` tables, skipped on a lane-scoped landing (`BENCH_ONLY_LANES`); **REMEMBERED** for T5's dense half and for the deletion half, which `if ns == {5}: continue` short-circuits
- Never publish a scale where comparators have rows and we do not; print what was withheld and why at export time. **GATE** withheld-scale guard in `export_web`
- Every artifact the page cites lives in this repository, and the superseded run is not left where it can be compared against. **GATE (report only)** `provenance_check.FEEDS`: an empty feed prints "(no result files)" and counts nothing. **GATE**: every pinned reader refuses when `<name>_<pin>` is missing
- Every overlay directory and top-level result file feeding a table records run conditions and a real version; "feeds a table" means "is opened by `make_paper_tables`". **GATE** `run_conditions`, `lane_files` and `_is_real_version` for the two lane files; **REMEMBERED** for the overlay directories T4 and T5 print, whose audit accepts any non-empty string
- A SNAPSHOT build's commit date must not predate a landmark commit. **GATE** `provenance_check.LANDMARKS`

## 2. How a cell is measured

- Published latency, throughput, percentile and memory cells run serial, one at a time, on the full cpuset. Permutation protects a ratio; it cannot restore an absolute level or a tail that never happened. **GATE** `runner.py` paper tier refuses `workers != 1`
- Every row names the instrument it was measured under (`instrument`, from `bench_common.INSTRUMENT`, which is `2026-11`; any other `BENCH_INSTRUMENT` is refused) and the machine (`bench_host`, refused at paper tier when unset). Rows from two instruments never share a table: a five-query analytics row beside a two-query one, or a relaxed-durability write beside an fsync one, is not a comparison. **GATE** `load_canonical`, `export_web._instrument_of`, `fairness_check.check_durability`
- The 2026-10 query set (two of its operations, `lsqb_q6` and `lsqb_q9`, excluded at the full graph network, DECISIONS #109), settled by DECISIONS #82d and extended by #104, the same on every engine of a table in its own language. Documents (6): TPC-C new-order and payment, and the four single-record operations on the same data set, 1,000 of each per repetition, ops/s over both transactions. Document analytics (5): TPC-H Q1 and Q6 plus three line-item queries with no join (top ten parts by revenue, count by ship mode, revenue by month), 100 runs each. Graph (7): point lookup, 1 hop, 2 hops, 3 hops filtered on the far end, insert, update, delete, the last three 1,000 each. Graph analytics (14): average friend age, friendships within a city, most friends, degree distribution, triangle count, and LSQB's nine pattern-matching counts (DECISIONS #104), 100 runs each, on the full social network at SF1. Dense vectors (3): search, insert into a built index then search, delete from a built index then search, the last two at the one-million tier only. Sparse vectors (1): search at three sizes. Time series (5, plus the 1 h range this lane already ran): newest reading, twelve-hour aggregate, double group-by, high-usage filter, group-by with ordering and limit, 100 runs each. Cross-model (4): the composed transaction, the same interrupted, a retrieval path, and a graph-filtered vector search. Lifecycle (4): open, one query, one write, close. Repetitions stay at five everywhere.
- Every timed query records warm latency at the median and the ninety-ninth percentile (`warm_<q>_p50_ms`, `warm_<q>_p99_ms`) and its own first-iteration number (`cold_<q>_ms`); the CELL records one cold column, `cold_first_query_ms` with `cold_first_query_name`, from the first query it ran after the database opened, and that is what a table prints (#89 as amended). No aggregated per-table statistic is published: no mean, no median, no geometric mean across query types. Peak memory and on-disk size stay on every row. Where a measurement does not apply the row records the reason in `cold_warm_na` or `cold_first_query_na` rather than leaving a blank. **GATE** `equivalence_check` for the digests; **REMEMBERED** for the split (F12, DECISIONS #89)
- Every timed query whose answer is deterministic records a canonical digest of that answer, order-insensitive unless the query defines an order, floats rounded to a fixed precision before hashing, with a small readable sample kept beside the digest so a disagreement can be read and not only detected. A query an engine cannot express is declared absent in its adapter, never silently skipped. **GATE** `equivalence_check`, which refuses a table whose engines disagree at one scale and names every declared absence (DECISIONS #88). The vector lanes keep recall against ground truth and the cross-model lane keeps its torn-state comparison, both stronger than a digest over an approximate answer. The server-restart lane's approximate vector read is held against the same engine's answer before every stop inside a repetition, and across repetitions (each builds the index again) by its recall against exact ground truth on the row (`REBUILT_PER_REP`; listed under E2b, not compared).
- A summed or averaged measure is declared numeric in its query's digest spec and compared as a number whatever type the driver returns, while counts and identifiers stay exact. ArangoDB's AQL `SUM` over integer-stored values returns an integer where every other engine returns a double, and a count rounded to six significant digits would let 1,234,567 and 1,234,568 agree. The declaration is per query and never per engine, so it cannot be used to make one engine's answer match another's. **GATE** `equivalence_check` over `bench_common.canonical_rows`
- The revenue total and the revenue by month count the rows they aggregate, and that count is compared exactly, because at the campaign's largest tier one lost row moves each sum by less than the digest's rounding (DECISIONS #94). **GATE** `equivalence_check`
- ArcadeDB SQL in this repository compares a numeric column through `BETWEEN` or a bound parameter, never against a bare decimal literal, which the engine parses at single precision so that the comparison loses the boundary value (upstream #7609, BUGS.md F42). **GATE** `equivalence_check`
- A served query that projects a temporal value is checked against its embedded twin, because the HTTP serializer prints a time bucket as a date and every bucket inside one calendar day collapses to one value (upstream #7610, BUGS.md F44); nothing is withheld today (`export_web.WITHHELD_CELLS` is empty); the withholding mechanism (`equivalence_check.KNOWN_DISAGREEMENTS` and `export_web.WITHHELD_CELLS`, moved together) is described once, in PUBLISHING.md. `KNOWN_DISAGREEMENTS` holds PostgreSQL + AGE's CRUD read-backs (apache/age#2587), whose cells publish with a note and are not withheld (DECISIONS #134). **GATE** `equivalence_check`
- **Three different things stop work, and they are not interchangeable.** A query **budget** stops one query; a whole-cell **cap** stops a cell; **abandonment** stops a query early when its budget cannot buy a useful measurement. Each is a property of the work, never of the engine (#85a), so no engine is ever given more room than the engine beside it.
- **Every cell has a time cap, and a cell that exceeds it is censored with the cap named.** The cap is a property of the tier, the same for every engine on it (`runner.TIMEOUT_BY_SCALE`), sized from the measured build at the tier below with headroom and then bounded so the matrix fits: the campaign runs about nine engines at five repetitions across several lanes, and an uncapped slow engine costs days to produce a row that says no more than a censored cell does. **The value is taken from the FASTEST engine's measured cell and the MEDIAN engine's projected one, never from the slowest**, for the same reason a budget uses the median: the slowest engine is the one the cap exists to bound, so sizing the cap to it would bound nothing. When the first repetition leaves no clean row the stage skips the rest, because repeating a timeout measures nothing; the table then shows one censored cell, not five. **GATE** `runner` (the cap), **REMEMBERED** the stage script (the skip). DECISIONS #105
- **The cap rule (2026-10-18) bounds every cell further.** Cell cap = min(the tier's cap, max(1800 s, 10 x ref)), where ref is the slower of the slowest ArcadeDB arm's median cell wall time and the median over all engines' medians for that cell (lane, scale, workload, durability class), from pass-1 timings; only ArcadeDB rows define the first, so no ArcadeDB arm is censored by the rule and a cap never rises. An arm censored by a timeout at a smaller scale of a lane is censored at every larger scale of the same lane, workload, and class: it is not run there, and neither is its overlay at a scale where its lane cell was censored. The rule is uniform across engines, applied at run time to cells not yet run (`make_2611_stages.py` lowers each cap and seeds the skip from `cap_rule_2610.json`, computed by `cap_rule.py`) and at report time to every row (`export_web.py`): a pass-1 arm-cell whose median wall time exceeds its rule cap is shown censored at the rule cap with its numbers withheld, and a missing larger-scale cell of an arm censored at a smaller scale is shown censored with a note naming the smaller scale. It exists because a cell that costs ten times what ArcadeDB and the median engine needed says no more than a censored cell does, and the pass would otherwise spend days producing it (DECISIONS #188 in the campaign notes).
- **A query's budget is derived per lane, per tier and per query, from the bench host's own frozen rows.** It is three times the MEDIAN engine's measured p50 for that query at that tier, times the lane's iteration count: the median because the slowest engine is exactly what a budget exists to bound, and the factor of three because it is the one judgement in the formula and it is the same everywhere. `derive_budgets.py` writes the table into `budgets.py` from the campaign's frozen rows (`--rows results/runs_paper_oct.csv` for October; its default is September's `results/runs_paper.csv`) and never from a laptop; `budget_lookup.budget_for()` reads it. Where a tier has no measurement the lookup falls back to the lane's old flat constant and stamps `<query>_budget_source` on the row saying so, so a projection can never be mistaken on the page for a measurement. A budget may vary by lane, tier and query, because those are properties of the work; it may never vary by engine. **A budget whose own roster is the survivors of a looser bound is withheld rather than published** (#106a): if the engines that left a row for that query and tier are fewer than half the widest roster answering it anywhere, the median is measuring its own selection, and the generator names the entry with its counts and falls back to the lane's constant. A query that exceeds it stops at the iteration it reached, its numbers are over those iterations, and the cell's other queries keep theirs. **GATE** `budget_lookup` (October instrument; September's lanes carry the flat constants). DECISIONS #106
- **A query whose budget cannot buy five iterations is abandoned after its cold pass.** The cold pass is already paid for, so it is kept and reported; `budget_lookup.abandon(cold_s, budget_s, iterations)` then asks whether the budget buys at least five iterations at the cold pass's own rate, five because a p50 over fewer is not a median of anything. When it does not, the row carries `<query>_abandoned` with the reason in seconds. The test uses only the engine's own cold pass, so it is a property of the work rather than of who is running it. The other queries in the cell are unaffected. **GATE** `budget_lookup.abandon`, called by `l1_tpc`, `l2_graph` and `l4_tsbs` (October instrument); `page_check` allows `\w+_abandoned` as a recorded field. DECISIONS #107
- An indexed lower bound is not assumed to return a whole run of equal entries: an ascending range seek starts where the binary search landed inside the run and loses `floor((k-1)/2)` of the k entries at the bound (upstream #7611, BUGS.md F46), which is why the revenue query disagreed only at the size where the loss landed on a qualifying row. **GATE** `equivalence_check`
- What answer checking cannot prove: DuckDB, PostgreSQL, and SQLite share a SQL dialect closely enough that a defect in a shape all three spell the same way would agree with itself, so the independent evidence comes from the engines with their own languages, MongoDB, SurrealDB, and ArangoDB on the document lane and SurrealDB (SurrealQL), ArangoDB (AQL), MongoDB (the aggregation pipeline), and DuckPGQ (SQL/PGQ) on the graph lane; the Cypher engines there share one query text with ArcadeDB. **REMEMBERED**
- Every timed WRITE runs at both durability settings (DECISIONS #90): the six document operations, the three graph writes, and the cross-model transaction, once relaxed and once strict. The class is a property of the cell, not a second measurement inside one, because ArcadeDB's `txWalFlush` is per database and SurrealDB's and QuestDB's are server flags; `runner.py --durability strict` is the axis, `durability_class` is on the row and in the canonical key, and the three engines with no knob (Neo4j and the arms built on it, DuckDB including its DuckPGQ arm, LadybugDB) run once and declare it. Bulk ingest and every read path stay at the relaxed setting. **GATE** `fairness_check.check_durability` (F10b)
- Bulk ingest runs at ONE durability setting on every lane (DECISIONS #90a). A bulk load commits in batches of thousands, so the flushes over a whole ingest are seconds and a second setting buys a second build rather than a second number. Checked once for OUR loaders, on the laptop at micro scale: the document, graph, and cross-model lanes each load the corpus inside the write cells that already run in both classes, so twenty-one engine-lane pairs carry a relaxed and a strict build, and every ratio landed between 0.92 and 1.14. No loader commits per row. A ratio far from one on a future lane is an artifact of the adapter, not a property of the engine. **REMEMBERED**
- A served SurrealDB cell that loses its WebSocket rebuilds the connection, re-authenticates, re-selects the namespace and database, and lets the call through once more; the sample taken across the drop is DISCARDED rather than published, and every SurrealDB row records `reconnects`, zero when nothing happened. The SDK's default 20 s ping and pong deadline is what dropped it, so the options are set explicitly and named on the row in `surreal_ws_options`. **GATE** `test_surreal_reconnect.py`; **REMEMBERED** for the field (DECISIONS #91)
- The two dense mutation operations run at the one-million tier only, and in the order delete-then-reinsert, which is what keeps their recall exact: the ground truth after deleting a set is the original one minus that set, and re-inserting exactly that set restores it, so nothing is brute-force recomputed on any arm. The victims are drawn from the ground truth so the deletions bite, and the row records how many deleted ids the index still returned, which must be zero. **REMEMBERED** `l3d_dense.mutation_victims`
- **A served engine's restart is timed on its own container, stopped and started in place** (DECISIONS #139 item 2, `l6_restart.py`): the same container the runner started, so the data, flags, cpuset, memory cap, and network name do not change; the lane drives `docker stop` (the image's own STOPSIGNAL, SIGTERM when it declares none, then SIGKILL after a grace no engine reaches; a kill is recorded as `stop_killed_after_grace`) and `docker start` through the Docker socket, which the runner mounts for that lane alone. A restart is timed until a fixed read answers EXACTLY as it did before the stop, split at the first successful liveness call (start) and the first right answer (first answer); every probe uses a fresh client so no driver's reconnect backoff is timed. Each cycle stops twice, after a session that wrote nothing and after one that wrote a fixed batch (each record committed), and the batch must read back after the restart that follows or the cell fails. The first cycle is warm-up (its stop flushes the whole load: `shutdown_after_load_s`, not printed). The host's page cache is warm by construction (a process restart on the same machine). **GATE** `l6_restart.restart_server`, the batch read-back
- Reps per build, warmup count, settle step and query set are properties of the lane, fixed before a driver is written. **REMEMBERED** (F4)
- Never print one-build-many-passes beside per-rep-builds in one table: the two shapes price different work and the table does not show which shape a row has. **GATE (report only)** `fairness_check.check_protocol_overlays` (F4)
- Warm queries must be disjoint from cold ones. Replaying one set cannot separate residency from recall of the same queries. **GATE** `sparse_multipass_driver` protocol for l3s; **REMEMBERED** and knowingly violated for l3d, whose driver replays the `test` set on every pass after 20 untimed warmups drawn from it
- Each engine gets its own vendor-documented settle step, timed inside build so the build is timed to a queryable index, and none is skipped. **REMEMBERED**
- Ingest timers must stop on the same completion semantics across a lane, or the rates price different work. **REMEMBERED**: a new time-series adapter must stop its timer at the same semantics its lane siblings do
- The dense and sparse lanes record `ingest_s` and `index_s` separately wherever the engine has the boundary (on the dense lane every arm except those `fairness_check.PHASE_SPLIT_DECLARED` names, which index while they load), additive, with `build_s` unchanged (DECISIONS #74 item 2). The document (`l1tpc`), time-series (`l4`), and cross-model (`e2`) lanes record the same pair through `bench_common.index_split` (FAIRNESS F14), and an arm whose index is defined before the load declares `index_before_load` instead (SurrealDB on the document and time-series lanes). Engines that index while ingesting record neither and carry the total with that as the stated reason. The dense table prints `ingest s` and `index s` beside the ingest+index pair; the sparse table prints the pair alone and records no split (pgvector's index build follows its load inside the same single timer); the September page keeps one pair. **REMEMBERED**
- Observe conditions from the daemon and the engine; never record what the launcher meant to do. A heap that disagrees with the request fails the cell. **GATE** `runner.observe_server`
- Overlay drivers sample their own peak memory from inside the container, started before the build. `run_conditions` records the ceiling, not the use. **GATE** `bench_common.SelfMemorySampler`
- The cgroup memory reading is valid only inside a bench container; record `host` so a reader knows which they have. **REMEMBERED**
- Time every phase of a lane and record the sum beside the runner's wall clock, so the residual is visible. **GATE** `phases_accounted_s` in `l3_sparse.py`
- Every lane prints `PHASE` markers as it runs (`bench_common.PhaseBeat`), and on a timeout the runner records `timeout_client_disk_mb` and `timeout_cpu_mem`, so a cell that dies inside its budget still says which phase it was in (BUGS.md F41). **GATE** `runner.py` timeout path
- On-disk size is the writable layer plus every declared volume, destinations read from the daemon, and it must settle (two readings within 1%, else `disk_settled=False` with both). A volume in an image with no `du` is sized from a helper container (BUGS.md F38). **GATE** `runner.container_disk`

- Prefer the loud failure: when a lane can measure something other than what was asked for, make it abort rather than annotate. **REMEMBERED**
- A server adapter that sends vectors as text must round-trip float32 exactly (`%.9f`, not `%.6f`). **REMEMBERED**: `precision_check.py` is a synthetic experiment that reads no artifact and nothing invokes it
- Never let a result object's Python type stand in for the finding, and abort an arm whose control operations moved nothing. **GATE** validity guard in `e2_hybrid.py`

- **The dense lane compares engines at matched recall (the beam sweep).** One latency at one search beam can be a faster, worse answer, so after the build and the cold pass the lane runs one more timed pass per beam value on the same built index (`dense_beam.py`): `ef` in 50, 100, 200, 400 for the HNSW engines (Qdrant `hnsw_ef`, Milvus `ef`, pgvector `hnsw.ef_search`, DuckDB `hnsw_ef_search`, Chroma `ef_search`, LanceDB `ef`, ArcadeDB `efSearch`, SurrealDB `<|k,ef|>`, MongoDB `numCandidates`, Elasticsearch `num_candidates`, Neo4j SEARCH `LIMIT`, LadybugDB `efs`), and ArangoDB's `nProbe` at 0.5, 1, 2 and 4 times the calibrated value. Each pass has its own 20 held-out untimed warm-ups and records `<ef|nprobe>V_recall_at_10`, `..._query_p50_ms`, `..._query_p99_ms`. The first pass is the cold pass this lane always ran, at ef 100: it alone keeps `query_p50_ms`, `query_p99_ms` and `recall_at_10` (the cold column), and its beam also reruns as a sweep point so that every point of the curve is a pass after the first. **The headline is the matched-recall cell: among the sweep passes whose recall@10 reaches the target 0.95, the lowest p50 (ties to the smaller beam), with the beam that won it** (`matched_r095_p50_ms`, `matched_r095_p99_ms`, `matched_r095_beam`); 0.90 and 0.99 are secondary columns (`matched_r090_*`, `matched_r099_*`). An engine that never reaches a target has no latency for it: the row says `matched_r095_status` = `not reached`, the table prints `not reached` with the best recall, and the cell is never replaced by a slower or lower-recall number. An engine with no beam setting (sqlite-vec, an exact scan; Memgraph; FalkorDB) runs no extra pass: its cold pass is the one point, `beam_kind` is `none` and `beam_na` says why. Every engine with a beam knob runs the same list and no cell is skipped for being slow, because a table that headlined some engines at matched recall and others at their default would mix two rules. The PQ arms keep their re-rank setting; only the beam moves. Under 2026-10 nothing is run and no field is written (`test_dense_ef_sweep.py`). **GATE** `test_dense_ef_sweep.py`

### Memory and disk per phase (issue #352)

Every row carries these fields. The code is `memory_probe.py`, and `bench_common.instrument_at_least("2026-11")` gates it (a row stamped by an earlier instrument has none of them).

- **What is read, and when.** At the end of each phase, between two timed sections, never inside one: `load` (the lane's build phase is done), `index_build` (its post-build wait for the index is done, for lanes that have one), `warmup` (an untimed warm-up is done), `queries` (all timed work is done, the engine still open), and `idle` (the same readings again after the engine has been left untouched for `BENCH_MEMPROBE_IDLE_S`, five seconds by default). A lane reaches the phases it has; a reading it does not take is absent, never a copy of the one before. A lane that builds and indexes in one timed phase has `load` as the end of both and no `index_build`.
- **How.** The lane prints its `PHASE` marker; at a marker that ends a phase it writes a request file into a directory the runner mounted into the client container and waits for the answer. The runner, on the host, reads the cgroup files of the cell at that moment and answers. There is no sampler thread inside the cell for this: the cost near a timed section is a 20 ms directory poll on the runner's own cores. The time spent, the full GCs included, is on the row (`phase_probe_s`, `mem_probe_gc_s`) and sits between phases, so no timed number includes it.
- **The headline, the same for every engine: owned memory at the end of the phase, `mem_<phase>_owned_mib`.** It is cgroup `memory.stat` `anon` plus `shmem`, summed over every container of the cell: the server container for a served engine plus the client's, the client process's container alone for an embedded one. Every engine has it whatever it is written in, it needs nothing from the engine, and it counts the shared-memory buffer pool of the PostgreSQL family as it counts a heap. The parts stay on the row (`mem_<phase>_anon_mib`, `_shmem_mib`, and the page cache `_file_mib`, which is context and never part of the headline), and so does the split per container (`mem_<phase>_server_owned_mib`, `_client_owned_mib`).
- **Peak per phase: `mem_<phase>_peak_mib`.** The largest total (`memory.current`, so it includes page cache) of each container during the phase, summed over the containers. When the kernel is 6.12 or newer and the runner may write the cgroup files, `memory.peak` is reset at every boundary through a descriptor the runner keeps open (a reset applies to reads through the same descriptor, so the whole-cell `peak_mib_sum` is unchanged) and the peak is exact (`mem_probe_peak_kind` is `kernel-reset`). Otherwise it is the largest `memory.current` the 0.25 s sampler saw in the phase (`sampled-0.25s`): a shorter spike is missed, and the field says so. `mem_probe_peak_reset` records which.
- **Added per runtime. Context only: these are not compared across engines.** JVM engines (ArcadeDB, Neo4j, Elasticsearch, the composed stack's Neo4j, QuestDB) get the heap at the end of the phase: `jvm_<phase>_used_after_gc_mib` where a full GC was forced first (the working set the engine needs) and `jvm_<phase>_used_mib` where it was not (garbage included, so never read as a working set), and in both cases `jvm_<phase>_committed_mib` (what the JVM holds from the kernel for its heap) and, where the JVM exposes it, `jvm_<phase>_direct_mib` (direct buffers: in-process through the buffer-pool MXBean for an embedded engine, from `jcmd VM.native_memory` for a server that runs with native memory tracking, otherwise absent). `jvm_probe_source` says `jpype` (the embedded JVM is asked in process) or `jcmd` (run in the server container). `jvm_forced_gc_phases` lists the phases that were measured after a forced GC. **A full GC is never forced right before a timed phase.** A collection at the end of a warm-up would hand a JVM engine a freshly collected heap for the timed queries that a native engine does not get, and would move the queries' own GC timing. The lane cannot see the next phase from a marker, so the rule is by phase: a GC is forced only at the end of the last timed phase (`queries`, read when the lane closes) and in `idle`; `load`, `index_build` and `warmup` are read without a GC, from `jcmd GC.heap_info` for a server or the runtime's memory counters for an embedded engine. The `owned` reading of a JVM engine is taken after the GC at `queries` and `idle`, and as the heap stands at the other phases, so compare owned memory across engines at `queries`, the page's column. Embedded engines also get `proc_<phase>_anon_mib` and `proc_<phase>_rss_mib` from `/proc/self/smaps_rollup` (the process's anonymous pages, and its resident set, whose difference is the file-backed pages): these are the closest per-process equivalents, comparable between embedded engines of any language. Non-JVM served engines (PostgreSQL, MongoDB, SurrealDB, Qdrant, Memgraph, ArangoDB and the rest) have no runtime to ask, and their extras are the cgroup parts above: `anon` against `shmem` against `file`.
- **What compares across engines and what does not.** `mem_<phase>_owned_mib` and its parts, and `mem_<phase>_peak_mib`, compare across every engine: they come from the same kernel counters of the same kind of container, and the page prints one headline column from them. `jvm_*` compares across JVM engines only and says nothing about a native engine; `proc_*` compares across embedded engines only. A JVM engine's `owned` and its `jvm_used_after_gc` differ by the JVM's slack (committed but free heap, metaspace, code cache, thread stacks, native memory): the first is what the container held, the second is what the engine needed, and neither replaces the other.
- **A pinned heap makes the kernel's numbers show the cap.** With `-Xms` equal to `-Xmx` the JVM commits the whole heap at start and touches it as it grows, so anon and RSS read near the cap whatever the engine needs, and a larger cap reads larger with the same workload. The ArcadeDB arms, embedded and served, do not pin the heap (`-Xms` is left unset), so their memory column reads demand up to `-Xmx`; the JVM arms that have a pinned tier heap (Elasticsearch, Neo4j) read the pin, and the other served engines keep following their vendors' documentation for the heap they start with. An unpinned heap is no cure for the headline: a JVM that has grown stays grown unless the collector returns the pages, which is why `jvm_used_after_gc_mib` sits beside it, and why a row records `jvm_<phase>_committed_mib` next to the heap the engine needed.
- **Disk per phase, the same way for every engine.** At the same boundaries the runner reads, for the container that holds the engine's data (the server container for a served engine, the client's for an embedded one), the bytes it is responsible for: the writable layer plus every declared volume, the reading `container_disk` already takes, here as one sample after a flush rather than the settled pair. `disk_<phase>_mib` is that reading, `disk_<phase>_data_mib` is the headline: it less the same container's empty-start reading (`server_disk_baseline_mb` or `client_disk_baseline_mb`), so it is what the workload left, comparable with `disk_data_mb`. `disk_<phase>_wal_mib` is the write-ahead log or journal alone, found inside the container by name (`*.wal`, `pg_wal`, `journal`, `translog`, `neostore.transaction.db.*`); an engine with another layout reads 0.0, which means none was found, and it is context, not a comparison. `disk_close_mib` and `disk_close_data_mib` are the runner's existing settled reading taken after the lane has closed the database; a phase reading of the same bytes can be lower or higher than it by what background compaction and checkpointing do in between, which is the point of reading both.
- **IO per phase: `io_<phase>_read_mib`, `io_<phase>_write_mib`.** The bytes the cell's containers read from and wrote to disk since the previous boundary (the cgroup `io.stat` counters are cumulative, so a phase is a difference; the first phase starts when the client container does), summed over the containers. The server's startup is not in `load`. The disk and IO readings are taken before the peak restarts, so the helper processes they start inside the container never land in the next phase's peak.
- **Where this stops.** A forced GC changes the heap for the phase that follows (a full collection empties young generations and caches the next phase would have found warm), which is why it runs only after the last timed phase and in `idle`, never before a timed phase, and is recorded in `jvm_forced_gc_phases`; and the lane waits for the answer, so the phases that follow a probe start a few hundred milliseconds later than they would have. A lane that prints no `PHASE` marker of the ones above (the lifecycle and restart lanes) takes no per-phase reading and keeps only the whole-cell fields.

## 3. How a comparison is kept fair

- Every container in a published cell gets the full 0-11 cpuset; a client/server pair shares that one cpuset rather than each getting its own cores, so CPU competition stays inside the deployment under test. **GATE** `fairness_check.check_cpuset` (F1) + the loader filter, for the client or embedded container only; **REMEMBERED** for the server side of a pair, whose `server_cpuset` no consumer reads
- Every backend at a (lane, scale) gets the same `--memory`/`--memory-swap` and, for JVM engines, the same heap (Neo4j and Elasticsearch excepted: each runs its vendor's memory rule, `vendor_memory.py`, DECISIONS #202). Raising a resource for one engine obliges a re-measure of every engine at that tier. **GATE** `fairness_check.check_envelope` (F3)
- Normalize a served topology before comparing: total is `srv_cap / mem_split`, never client + server. **GATE** `_total_envelope` in `fairness_check`
- Do not compare a setting to its own absence: heaps are compared only among engines that have one, and a missing heap on an ArcadeDB row is reported as a recording gap. **GATE** `check_envelope`
- Every dense backend at a scale gets the same effective base-layer degree, read in each engine's own unit (ArcadeDB `maxConnections` as-is, hnswlib-family `M` doubled at layer 0). A row recording no degree FAILS; sqlite-vec is exempt as an exact scan, and an index with no degree at all is matched by effect instead (F7). Stamp the matched parameter from one shared function, called from both the lane and its bespoke driver. **GATE** `fairness_check.check_degree` (F7) + `l3d_dense.degree_stamp(backend)`
- Check the rows the table prints. Where a table reads an overlay, the fairness checks read that overlay too. **GATE** `_dense_rows()` swap in F3/F7
- Fit every engine's thread pools to the cpuset via `sched_getaffinity`; `os.cpu_count()`, `nproc --all` and `/proc/cpuinfo` in an adapter are the bug. **REMEMBERED** (F6; the three DuckDB lanes that ran oversubscribed were fixed on main, DECISIONS #101; the retired September rows were measured oversubscribed)
- Verify the shared cpuset equalizes **use**, not merely the resource, before comparing p50s. **REMEMBERED** (F8 holds the measurement)
- When a campaign re-measures one engine and carries the others forward, re-run one untouched comparator as a control and record its old-vs-new delta beside the table it licenses. If the control does not reproduce, the tier is re-measured in full. **REMEMBERED** (F9)
- Measure every row in one table on the same engine release as the row beside it, so a version difference cannot be read as a configuration difference. **GATE** T4 and f8 only; **REMEMBERED** elsewhere (F5)
- Never divide a number from one experiment by a number from another and call the quotient a cost. **HAND-RUN** `claims_check._tentag` and the dense cold/warm boundary note
- Equalize a comparator's default only where leaving it makes the comparison apples-to-oranges (the four categories in section 7). **REMEMBERED**
- A durability default is relaxed only as a matched class over the whole table, never for one arm: from 2026-10 every engine that has the setting commits without waiting for the disk, each engine's setting is read out of the engine rather than assumed, and the row records what it ran as `durability` (DECISIONS #81). **GATE** `fairness_check.check_durability` (F10)
- Every timed write runs at both durability settings and ingest at one, as section 2 says (DECISIONS #90, #90a); whether our loaders commit per batch rather than per row is settled once by a laptop check, never by a campaign axis. **GATE** `fairness_check.check_durability` (F10)
- The strict setting is a fixed per-commit tax set by the device, so under strict durability the engines converge and the ratio between the two settings is inversely proportional to how fast an engine's relaxed path is. A published relaxed write therefore measures how well an engine avoids the disk as much as how fast it writes; the framing cuts against us as much as for us, since ArcadeDB embedded's fast relaxed document insert is what makes its own multiple one of the largest. **REMEMBERED**
- A fix that costs the rival a round-trip goes only in the untimed path, or the round-trip is charged to their latency. **REMEMBERED**
- State the consequence of the memory contract that cuts against us: the JVM heap lives inside the container cap, so ArcadeDB's 24 GiB heap leaves about 12 GiB for JVM overhead and page cache while non-JVM comparators have all 36 GiB. Equal caps are what we can enforce. **REMEMBERED**
- Keep `fairness_check.DISCLOSED` empty unless an override is live, and delete a disclosure the moment the asymmetry it describes is fixed. **REMEMBERED**

## 7. Defaults and sanctioned overrides

We run every engine as shipped, and override a default only where leaving it would make the comparison meaningless. Four sanctioned categories:

1. **Resource fitting** (always applied): heap, thread pool and memory settings that fit an engine to the cell's cpuset and memory envelope. Envelope equality, not tuning.
2. **Vendor settle step**: documented bulk-load-then-query preparation, timed inside build (section 2).
3. **Operating-point matching**: where defaults put engines at different points of a quality/latency tradeoff, move them onto one point, because a latency comparison at unequal recall compares nothing.
4. **Documented escape hatch**: a default that is demonstrably pathological, tuned to the vendor's own recommendation, with the same care applied to every backend in the lane.

What we never do: per-system expert tuning beyond vendor guidance, or tuning ArcadeDB with insider knowledge not applied to comparators.

An override nobody can find is a defect, whichever way it moves the number. Every override is stamped on the row where a field exists (`es_prune`, `degree_param`, `degree_family`, `heap`, `server_heap`) **and** named in reader-facing text (table caption or page condition). `DISCLOSED WHERE = NOWHERE` marks an override not yet disclosed (the column has none left, CAMPAIGN.md section 7, item 21; `test_overrides.py` fails on a new one). A "generated sentence" below is printed under every table that shows the arm (for a stamped row, only from rows that carry the stamp). Every override a table shows is registered in `override_registry.py`, which holds the row field the adapter reads back from the engine, the generated sentence, and the checks (`page_check` for the sentence, `fairness_check` F15 for the stamp, and `test_overrides.py`, which reads this table); a row's last column cites its registration as `override: <key>`.
